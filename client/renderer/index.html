📖 使用手册


        

          
🚀 快速上手(4 步)

          
设置 → 常规 → 填写「API 地址 / API Key / 审查模型」→ 点「保存全部设置」(保存时会自动校验, 配置错误当场提示, 校验通过才会保存)。

          
设置 → Git 仓库 → 新增, 填入 Git 地址 / API Token / 本地目录; 或直接在顶部选择已配置仓库。

          
左侧导航: 待合入 MR / 历史 MR / 提交树, 点选一条 → 「🔍 开始审查」。

          
审查结果每条可勾选 → 「📤 回填评论」只回填所选项; 「🔧 自动修复」自动生成修复分支并(默认)推送远端。

        


        

          
🗂 左侧导航(与设置一致)

          
返回主界面(默认激活「待合入 MR」)。

          
当前未合并的 MR, 可审查/回填/修复。

          
已合入 ✅ / 已关闭 ⛔ 的 MR, 可再次选中审查。

          
按分支查看提交, 可对单个提交审查(回填到关联 MR 或提交评论)。

          
本机保存的每次审查记录, 可回看评论/修复建议, 且支持勾选后再次回填(仓库一致时才允许)。

        


        

          
💬 审查与回填

          
审查偏好可设「中文」—— ocr 直接输出简体中文(无需再翻译); 设「自动」则英文原文 + 智能翻译。

          
每条评论前有勾选框, 统计行支持「全选 / 全不选」; 「📤 回填评论」仅回填勾选项, 已在服务器存在的自动去重。

          
历史 Review 里勾选评论后点「📤 回填评论」可补推到对应 MR/提交; 若记录属于其它仓库且该仓库已配置, 会自动切换过去再回填(日志提示「已自动切换到记录所属仓库」), 无需手动操作。

        


        

          
🔧 自动修复与推送

          
修复分支建立在 MR 的源分支上(如 br_feature_xxx), 与合入目标是 br_dev_xxxx 无关。

          
每个问题一个增量 commit, 标题「【fix】…」, 描述含「【问题单号】MR#N」「【影响性】高/中/低」。

          
审查偏好「修复后推送远端」默认勾选; 修复完成自动 push 到远端, 研发 git fetch && git checkout fix/ai/... 即可查看/ cherry-pick 到自己的源分支。

        


        

          
⚙️ 设置项速查

          
API 地址(head 幂版本须带 /v1)、API Key(不再使用系统环境变量)、审查模型(「获取模型列表」刷新)。

          
单机服务地址 http://127.0.0.1:3001 与客户端 Token(卡控/记录推送)。

          
自动回填、自动修复、修复后推送远端、审查输出语言、审查并发(1-32)、审查超时(默认 60 分钟)、推送失败上限。

          
设置 → 定时任务: 客户端自动扫描待合入 MR(不依赖服务器)。可按仓库创建多个任务, 每个任务可选频率(30分钟/小时/2小时/4小时/6小时/12小时/天)与每日开始时间(留空=立即); 任务列表随时启动/停用/删除。发现新 MR 自动刷新对应仓库列表。

        


        

          
⌨️ 快捷键 / 小技巧

          
放大 / 缩小整个界面布局; Ctrl+0 复位 100%(重启后保持上次大小)。

          
运行日志可直接鼠标选中文字后 Ctrl+C 复制; 右键「📋 复制所选」与 Ctrl+C 完全一致(复制当前选区, 所见即所得)。右键「🧹 清空日志」。

          
右上「审查结果」上方的仓库下拉可直接切换, 列表/审查随之更新。

        


        

          
🩺 常见问题排查

          
按提示核对 API 地址(是否 /v1)/ Key(401?)/ 模型名(404? 从「获取模型列表」选择)。校验不通过会阻止保存。

          
多为配置问题: 请到「常规」确认 API 地址/Key/模型已正确保存(保存通过校验即说明可用), 并覆盖安装最新版本。

          
大 MR 默认 60 分钟超时; 可在「审查偏好 → 审查超时」调大, 或调大「审查并发」加速。

          
已自动清理残留脏审查记录; 若仍失败, 把日志右键「复制日志」发给管理员排查。

          
历史记录所属仓库不在当前配置列表时, 才会提示; 到「设置 → Git 仓库」添加该仓库后再回填。已配置的仓库会自动切换。
