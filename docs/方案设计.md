# CodeReviewSystem 方案设计

- 版本：v1.2　更新：2026-08-20　适用：v1.1.x

## 1. 总体架构

```
┌────────────────────── Electron 客户端 ──────────────────────┐
│ renderer(index.html)         main.js(主进程, IPC)            │
│  左导航/审查结果/日志/设置       ┌───────────┬──────────────┐  │
│                              │review-backend │ fix-engine  │  │
│                              │  (git+api+ocr) │(自动修复)   │  │
│                              ├───────────┼──────────────┤  │
│                              │ report-queue  │ scheduler(定时)│ │
│                              └───────────┴──────────────┘  │
│  ocr native(便携) → 模型 API(GitLab/Gitea)                    │
└───────────────┬────────────────────────────────────────────┘
                │ 每日卡控 / 记录推送(HTTP + 客户端 Token)
┌───────────────▼────────────────┐      ┌──────────────────────┐
│  Node/Express 服务端(:3001)     │      │  GitLab / Gitea(:3000)│
│  PostgreSQL(codereview, 10表)   │      │  MR/评论/分支          │
│  管理后台(web/)                 │      └──────────────────────┘
└────────────────────────────────┘
```

## 2. 关键设计决策（与实现一致）

| # | 决策 | 说明 |
|---|---|---|
| D1 | **ocr native 直调 + 便携配置** | 跳过 js 启动器直接执行 `opencodereview.exe`；通过 `USERPROFILE=程序目录` 将配置重定向到 `程序目录/.opencodereview`，内网分发即用、零全局配置；打包版从 `app.asar.unpacked` 推导真实路径（避免对 `app.asar`（文件）建目录失败）。 |
| D2 | **LLM 保存即校验，不依赖系统环境** | 点保存时对 地址/Key/模型 实测（`/v1/models` + 一次极小 `chat/completions`），401/404 当场拦截；只从软件内配置取 Key（先后备便携 config），不再读系统环境变量。 |
| D3 | **回填三级复用** | ① 本次会话 `lastReview`（同仓库+同 MR）→ ② 本地历史 `reviews-history.json`（按 MR！N+仓库 / 提交 sha，最新一条）→ ③ 都没有才重新审查。 |
| D4 | **回填自动切换仓库** | 历史回填按记录 `repoKey(url|project|repoDir)` 匹配已配置仓库并自动切换（写 activeRepo + 重建 backend + 通知渲染进程刷新下拉与列表），未配置才提示。 |
| D5 | **选择性回填** | 评论勾选（默认全选 + 按等级快捷），`postComments/commit:post` 支持评论子集参数。 |
| D6 | **修复基于源分支 + 逐问题增量 commit** | 修复分支建于 MR 源分支（`srcBranch`），每问题一个 commit；`【fix】标题 + 【问题单号】【影响性】描述`；默认推送远端（`autoPushFix`，push 失败不中断）。 |
| D7 | **定时任务客户端化** | 主进程每分钟扫描所有启用任务（每个任务独立临时 backend，不打断当前仓库），支持按仓库多任务、频率、每日开始时间、启停；发现新 MR 通知渲染进程按仓库过滤刷新。 |
| D8 | **审查进程退出语义** | `code 0` = 正常完成（等回调收尾）；`_stopReq` = 手动停止；SIGTERM+code null = 超时（设置项,默认 60min）；其它 = 8 秒兜底拿 stderr 报真实原因；Windows 停止用 `taskkill /T` 杀进程树。 |
| D9 | **脏 review 自愈** | 回填前扫描并删除服务器上引用本仓库不存在对象的 PENDING review，防止 Gitea LineBlame 永远 500。 |
| D10 | **历史记录本地持久化** | `reviews-history.json`（500 条上限，含 repoKey/iid 或 sha/comments），离线可选、可二次回填、打开 MR 网页。 |
| D11 | **工作区多仓库 key** | `currentRepoKey = url|project|repoDir`，审查/回填/修复复用均校验同仓库，杜绝跨仓库误用 sha。 |

## 3. 核心流程

### 3.1 审查流程
```
选择 MR/提交 →(renderer)runReview/runCommitReview
  → syncOcrConfig(客户端 LLM 配置写入便携 config, provider=app)
  → runNative / runNode 执行 ocr
       env: OCR_LLM_URL/TOKEN/MODEL(仅有效时注入)
            OCR_NO_UPDATE=1, OCR_MODEL, USERPROFILE=便携目录
       args: review --from <base> --to <head> --format json
             --model --concurrency --timeout(设置-5min)
             --background(中文指令, 当 ocrLang=zh)
  → 退出语义判定(正常/停止/超时/异常, 拿 stderr)
  → 成功: translateComments(CJK 跳过翻译) → saveReviewHistory
          → reportReview(队列) → (autoPost? 回填) → (autoFix? 修复)
```

### 3.2 回填流程（三级复用 + 自动切仓）
```
doPost(勾选子集)
 → currentHistory? (历史记录) → iid/sha + repoKey + 历史评论
 → review:post(iid, comments, expectRepoKey, historyReview)
     ≠当前仓库 → repoIndexByKey 命中 → activateRepoIndex(自动切)
     复用: historyReview → lastReview → reviews-history.json 找回 → 都没有 → 重审
 → backend.postComments(iid, log, review, selectedComments)
     Gitea: POST /pulls/{iid}/reviews(COMMENT, commit_id=mr.sha) + 脏review清理 + 去重
     GitLab: POST /merge_requests/{iid}/discussions(带真实 base/start/head sha)
     评论体 fmtCommentBody: 描述 + 📄问题代码 + 🔧修复建议(带语法高亮)
```

### 3.3 自动修复流程
```
doFix → fix:run(iid, review)
 → base = review.srcBranch(源分支!) | 'commit:<sha>' | main
 → fix-engine.runFix:
     checkout/建 源分支 → branch -B fix/ai/<base>-mr-N
     逐问题: 读文件 → 小文件整文件重写 / 大文件 unified diff → git apply 校验
             → git add → commit(-m 【fix】标题, -m 【问题单号】…) → 记录 sha
     autoPushFix → git push -u origin fixBranch(失败不中断)
 → reportFix(队列) → 修复完成提示"研发可 git fetch 后切分支修改"
```

### 3.4 定时任务
```
启动/配置保存 → restartScheduler(1 分钟 tick)
schedTick: 遍历 enabled 任务 → now ≥ nextScanTime(有 startTime: 当天该时刻首算; 无: 立即)
 → scanRepoForSched(独立临时 backend, listMRs)
 → 新 MR? pushLog + mrs:refresh(repoIndex)  → renderer 仅当前仓库刷新
 → schedule:tick 事件 → 更新任务列表上次触发时间
```

## 4. 接口清单（IPC 主要）

| 通道 | 说明 |
|---|---|
| review:run / commit:post / review:stop / review:post | 审查、提交回填、停止、MR 回填 |
| fix:run / fix:commit | 自动修复（MR/提交） |
| mrs:list / mrs:history / commits:list | 待合入 MR、历史 MR、提交树 |
| reviews:list | 历史 Review |
| schedule:list / create / update / delete | 定时任务 CRUD（客户端） |
| config:get / config:save / llm:models / llm:validate | 配置与模型校验 |
| gate:heartbeat / gate:recheck / gate:status | 每日卡控 |
| server:test / clip:write / open:url / open:commit / ui:zoom | 连接测试/剪贴板/外部打开/缩放 |
| 事件: log / repo:switched / mrs:refresh / schedule:tick | 日志、仓库切换、定时刷新、任务状态 |

## 5. 配置设计
- config 字段：repos[]、activeRepo、model、llmBaseUrl、llmApiKey、serverUrl、clientToken、autoPost、autoFix、autoPushFix(默认开)、reviewDepth、ocrLang、concurrency、reviewTimeout(默认60)、pushMaxTries、scheduleInterval(旧)、schedules[]（任务: id/name/repoIndex/intervalMin/startTime/enabled）、theme、fontSize、uiZoom。
- ocr 便携 config（程序目录 .opencodereview/config.json）：provider=app、custom_providers.app(url/api_key/model)、language(zh→zh-CN)。
