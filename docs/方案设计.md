### 关键设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 客户端框架 | Electron + 原生 HTML/JS(沿用现有 CodeReviewTool) | 已有可复用代码,打包经验成熟 |
| 服务端 | Node.js + Express + node-cron | 与客户端同栈,部署简单,Windows/Linux 通用 |
| 数据库 | PostgreSQL | 用户指定;统计数据量级(10 万级)完全胜任 |
| 审查引擎 | 阿里 open-code-review(ocr)CLI | 已验证:精准度、去重、回填、Gitea/GitLab 双支持 |
| 授权模型 | 服务端签发 client token + 心跳 | 客户端离线即禁用审查,符合"连不上就不能 review" |
| 定时任务 | 服务端 node-cron 调度,执行器复用审查流水线 | 统一审查逻辑,客户端/定时任务共用一套代码 |
| 离线缓冲 | 客户端本地 SQLite(或 JSONL)队列,重连后补传 | 满足 NFR-06 |

## 2. 客户端方案

### 2.1 模块划分

```
client/
├── main.js               # Electron 主进程: 窗口/IPC/授权门禁
├── preload.js            # 安全桥接
├── renderer/
│   ├── index.html        # 主界面(提交树 + 审查结果)
│   ├── settings.html     # 设置中心
│   └── css/js/           # 样式与逻辑
├── backend/
│   ├── review-backend.js # 审查调度(已有, 扩展)
│   ├── git-service.js    # git 命令封装: 提交树/分支/diff/修复分支
│   ├── fix-engine.js     # 自动修复引擎(逐问题 commit)
│   ├── usage-tracker.js  # 用量采集(token/请求次数)
│   ├── report-queue.js   # 数据上报 + 离线缓冲
│   └── auth-gate.js      # 服务端连接/授权门禁
└── config.json           # 本地配置(userData)
```

### 2.2 授权卡控流程(每日进入时)

```
客户端启动/每日进入 → 读服务端配置 → GET /api/auth/heartbeat (client token)
    ├─ 200 → 本次会话授权通过, 审查功能可用
    ├─ 401 → token 无效, 禁用审查 + 提示重新配置
    └─ 网络错误 → 离线模式: 提交树可用, 审查功能当日禁用(每日卡控)
本地缓存: 审查/修复/用量记录先写本地队列, 心跳/重连成功后批量补推
定期(每 30s)尝试重连推送; 本地队列上限 5000 条
```

### 2.3 提交树实现

- 数据来源:`git log --graph --all`(全分支)或 `git log`(当前分支),解析为树节点
- MR 关联:对每个 commit SHA 调用 Git 服务 API(`/commits/:sha/pulls` Gitea / `commit/:sha/merge_requests` GitLab),缓存映射
- 渲染:虚拟滚动(万级提交),节点徽标(MR/分支/HEAD)

### 2.4 自动修复引擎

```
触发: 审查完成 + 设置开启自动修复
流程:
1. 取 MR 源分支的远端 SHA → 本地创建 fix/ai/<mrId>-<ts>
2. 按严重程度降序取问题清单
3. 对每个问题: 读取上下文 → 调 LLM 生成补丁 → 应用 → 独立 commit
   commit message: fix(ai): #<序号> <问题简述>  [ref: MR!<id>]
4. 全部完成 → 汇报 (分支名/问题数/commits) → 上报服务端
5. 研发本地 review 决定推送/丢弃
安全边界: 修复分支永不自动 push; 补丁应用失败跳过该问题并记录
```

### 2.5 用量采集

- 在审查调用点包装:记录 `模型 / input_tokens / output_tokens / 请求次数 / 耗时`
- ocr 输出 manifest 含 token 统计(已验证),补丁生成调用自行统计
- 随审查记录一起上报;本地累积待重传

## 3. 服务端方案

### 3.1 模块划分

```
server/
├── src/
│   ├── index.js            # 入口: Express + 静态管理页
│   ├── db/
│   │   ├── pool.js         # pg 连接池
│   │   └── schema.sql      # 建表脚本
│   ├── api/
│   │   ├── auth.js         # 管理员登录 / client token 签发
│   │   ├── reviews.js      # 审查记录 CRUD + 明细
│   │   ├── usage.js        # 用量记录 + 聚合
│   │   ├── stats.js        # 统计报表聚合查询
│   │   ├── tasks.js        # 定时任务 CRUD + 立即执行
│   │   └── admin.js        # LLM 配置 / 授权 / 健康检查
│   ├── scheduler.js        # node-cron 调度器
│   ├── executor.js         # 任务执行器(复用审查流水线)
│   └── llm.js              # LLM 调用封装(多 provider)
├── web/                    # 管理 Web UI (静态页 + 图表)
└── config.json             # 端口 / PG 连接 / LLM 配置
```

### 3.2 审查流水线(服务端定时任务复用)

```
定时任务 → 拉取远端仓库(或复用客户端本地仓) → 枚举目标(MR 列表/分支) →
ocr review → 问题入库 → 用量入库 → 生成报告 → (可选)回填评论
```

### 3.3 数据上报协议(客户端 → 服务端)

| 端点 | 用途 |
|---|---|
| `POST /api/reviews` | 审查记录(含问题数组、token、耗时) |
| `POST /api/fixes` | 自动修复记录 |
| `POST /api/usage` | 用量明细 |
| `POST /api/heartbeat` | 客户端心跳/授权校验 |
| `GET  /api/stats/...` | 管理端统计 |

### 3.4 部署形态(单机部署,参考 PM 项目)

- **服务端**:单机部署(Node.js),`db/schema.sql` 一键建库 → `npm start` 即起(3001 端口)
- **数据库**:本机安装的 PostgreSQL 15+(已运行于 5432),连接串写入服务端 config.json
- **目录结构参考 PM**:backend(接口)+ web(管理前端静态页)+ db(schema.sql)+ deploy(启动/备份脚本)
- **管理 Web**:服务端自带静态页面,浏览器访问 `http://<ip>:<port>/`
- **一键启动脚本**:参考 PM 的 `start-dev.bat/ps1`,自动完成建库检查、配置生成、启动服务

## 4. 安全设计

| 项 | 方案 |
|---|---|
| 客户端 ↔ 服务端 | 固定 client token(服务端生成,配置进客户端);HTTPS 可选 |
| 管理员登录 | 账号密码 + session(JWT),初始账号由 `init-admin` 脚本创建 |
| Git 凭据 | 客户端本地存储,Windows DPAPI 加密 |
| LLM Key | 存服务端 config.json(权限 600);客户端可覆盖但不上报 |
| 日志脱敏 | 日志不打印 token/密钥 |

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| ocr CLI 版本升级 API 变化 | 封装适配层,锁定版本 |

## 附录 A: 设置中心设计(参考 Codex 风格, REQ-S01~S08)

### 交互风格
- **分组卡片式设置页**(非弹窗):左侧分组导航(连接 / Git / 审查 / 外观 / 高级),右侧配置项
- 开关式配置项(Toggle),修改**即时生效并持久化**(config.json)
- 深色主题为默认,支持 深色 / 浅色 / 跟随系统 三档切换

### 设置项清单

| 分组 | 设置项 | 类型 | 默认 | 说明 |
|---|---|---|---|---|
| 连接 | 服务端地址 | 文本 | - | 卡控/上报目标 |
| 连接 | 客户端 Token | 密码 | - | 服务端管理后台创建 |
| Git | Git 服务地址 | 文本 | - | Gitea/GitLab |
| Git | API Token | 密码 | - | 审查/回填凭据 |
| Git | 项目(owner/repo) | 文本 | - | 远端项目路径 |
| Git | 本地仓库目录 | 路径 | - | 提交树/审查工作区 |
| 审查 | 自动回填评论 | 开关 | 关 | 审查完成自动回填 Git |
| 审查 | 自动修复分支 | 开关 | 关 | 审查完成自动建修复分支(仅本地) |
| 审查 | 审查深度 | 选择 | 标准 | 快速/标准/深度(映射 ocr 参数) |
| 审查 | 模型 | 选择 | deepseek-v4-flash | 审查 LLM |
| LLM | Base URL | 文本 | opencode 网关 | 自动修复引擎用 |
| LLM | API Key | 密码 | 环境变量兜底 | 自动修复引擎用 |
| LLM | 修复模型 | 文本 | deepseek-v4-flash | 修复专用模型 |
| 外观 | 主题 | 选择 | 深色 | 深色/浅色/跟随系统 |
| 外观 | 字体大小 | 选择 | 中 | 小/中/大(代码区联动) |

### 自动流程(开关联动)

```
审查完成(卡控已通过)
  ├─ 自动回填=开 → 自动 postComments(去重)  → 日志提示
  └─ 自动修复=开 → 基于 MR 原始分支 runFix    → 每问题一 commit(仅本地)
开关均为"审查时读取", 修改后对下一次审查生效
```

### 主题实现
- CSS 变量双主题(深色 :root / 浅色 [data-theme=light]),切换即改 `document.documentElement.dataset.theme`
- 跟随系统: `prefers-color-scheme` 媒体查询监听
- 字体大小: html 根字号(小 12px / 中 13px / 大 15px),代码区用 em 联动
