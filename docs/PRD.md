# CodeReviewSystem 需求文档(PRD)

- 文档版本：v1.2
- 更新日期：2026-08-20
- 适用版本：v1.1.x（与客户端实际功能一致）

## 1. 产品概述

**CodeReviewSystem** 是一套 AI 代码审查工作台：**Electron 桌面客户端 + Node/Express 单机服务端 + PostgreSQL**。对 GitLab/Gitea 仓库的 **MR / 提交** 自动做 AI 代码审查，支持评论一键回填、基于源分支的自动修复（逐问题增量 commit）并推送远端，供研发直接查看与 cherry-pick。

## 2. 目标用户与核心价值

| 用户 | 价值 |
|---|---|
| 研发工程师 | MR 合入前自动审查；修复分支逐问题提交，可 cherry-pick 到自己的功能分支 |
| 团队/个人 | 审查结论(问题+修复建议)沉淀在 GitLab/Gitea 评论区，代码评审有据可依 |
| 企业与内网 | 客户端配置随程序走（便携化），模型/密钥零全局配置，适配内网离线环境 |

## 3. 功能需求

### 3.1 审查对象与动作
- 支持多仓库（GitLab / Gitea），左侧按页签组织：**待合入 MR / 历史 MR / 提交树 / 历史 Review**。
- 对待合入 MR、历史 MR、任意提交执行 AI 审查，输出：问题描述、严重级别、问题代码、**修复建议**。

### 3.2 审查配置（设置页）
- **模型服务**：API 地址 / API Key / 审查模型（可拉取模型列表）。
  - Key 与模型**来自软件内配置**（不依赖系统环境变量）；保存时**自动校验**（地址可达 + Key 真实有效 + 模型存在），校验失败阻止保存并给出具体原因。
- **审查偏好**：自动回填、自动修复、修复后推送远端（默认开）、审查输出语言（自动/中文/英文）、审查并发（1–32）、审查超时（默认 60 分钟）、推送失败上限。
- **定时任务**：客户端定时扫描待合入 MR（详见 3.6）。
- **Git 仓库**：新增/编辑/删除仓库（名称、Git 地址、API Token、项目路径、本地目录）。
- **服务端**：服务端地址、客户端 Token（每日卡控）。
- **外观**：主题（深/浅/跟随系统）、字号、界面缩放快捷键 Ctrl+加号/减号（范围 −2~+3，重启保持）。
- **高级**：超级管理员授权（免服务端验证）。
- **使用手册**：内置完整操作系统指引。

### 3.3 审查结果与回填
- 审查结果按严重级别统计（严重/中等/轻微），每条评论含：描述、问题代码、修复建议（可复制）。
- **选择性回填**：每条评论前勾选框（默认全选），支持「全选 / 全不选 / 仅严重 / 仅中等 / 仅轻微」；回填仅提交勾选项，服务器已有的自动去重。
- 回填评论体统一包含：`问题描述 + 问题代码 + 修复建议`（代码块自动按文件扩展语法高亮），**修复建议随评论推送到 GitLab/Gitea**。
- **回填三级复用**（不再重复审查）：① 本次会话刚审查的结果 → ② 本地保存的历史审查结果（按 MR/提交 + 仓库）→ ③ 均无才重新审查。
- **自动切换仓库**：回填历史记录时若所属仓库为已配置仓库，自动切换到该仓库再回填。

### 3.4 自动修复与推送
- 基于 **MR 源分支** 创建修复分支 `fix/ai/<源分支>-mr-<N>`（提交审查为 `fix/ai/commit-<sha8>`）。
- **每个问题一个增量 commit**，便于研发 cherry-pick 到自己的功能分支。
- 提交模板：
  ```
  标题: 【fix】<类别> <文件>:<行> <摘要>
  描述: 【问题单号】MR#<N> / commit/<sha8>
        【影响性】高/中/低 · <说明>
  ```
- **修复后推送远端（默认开启）**：`git push -u origin <修复分支>`，push 失败不中断（本地分支保留并可手动重试）。
- Commit 消息模板：`【fix标题 + 描述体】`（标题格式 `fix(ai): …` → 已规范为 `【fix】…`）。

### 3.5 历史 Review
- 每次审查完成后自动本地持久化（`%APPDATA%\code-review-tool\reviews-history.json`，最多 500 条），离线可查。
- 「历史 Review」独立页签：新→旧列表（时间/仓库/对象/条数/评论摘要），选中可查看完整评论/修复建议。
- 历史记录中的 MR 可点击「进入 MR」直接打开网页；历史评论支持勾选后二次回填。

### 3.6 定时任务（客户端）
- 运行在**客户端主进程**（不依赖服务器定时），随应用启动。
- **按仓库创建多个任务**：每个任务指定名称、仓库、扫描频率（30分钟/1/2/4/6/12小时/每天）、**每日开始时间**（留空=立即，之后按频率）。
- 任务列表每项可随时**启动/停用/删除**，显示上次触发时间。
- 扫描独立性：为每个任务单独建立连接，**不打断**当前查看的仓库；发现**新的待合入 MR** 时日志提示并自动刷新对应仓库列表（当前不在该仓库则不打扰）。

### 3.7 服务端（单机）
- Express + PostgreSQL；提供管理后台、仓库/记录管理。
- 每日卡控：客户端心跳授权（服务端 Token / 超级管理员本地授权兜底）。
- 审查/修复/使用记录由客户端推送（队列持久化，断网积压、重试上限、手动重推）。

## 4. 非功能需求
- **便携化**：ocr（open-code-review）native 版配置目录通过 `USERPROFILE` 重定向到程序目录 `.opencodereview`，随程序走、零全局配置；内网分发整个程序目录即可。
- **兼容性**：Windows 10+，本地 PostgreSQL 单机；GitLab 与 Gitea 双后端。
- **稳定性**：审查进程退出语义严格区分（正常完成/手动停止/超时/异常），停止评审按进程树终止；回填前自动清理服务器脏审查记录（防 LineBlame 500）。
- **安全**：凭据不入库不落日志；`.gitignore` 排除 node_modules/dist/.opencodereview/server 配置与数据。

## 5. 范围与边界
- 本期不做：多用户协作、邮件通知、日程集成。
- 修复是否提交远端由研发决定（默认自动推送修复分支，可关闭）。
