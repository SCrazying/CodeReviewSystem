# CodeReviewSystem 系统设计

- 版本：v1.2　更新：2026-08-20　适用：v1.1.x

## 1. 技术栈

| 层 | 技术 |
|---|---|
| 客户端 | Electron + 原生 HTML/CSS/JS（renderer）+ Node 主进程（IPC）。无前端框架，单页 index.html |
| ocr | open-code-review（阿里巴巴）**native 二进制 opencodereview.exe** 直调（打包含于 app.asar.unpacked） |
| 服务端 | Node/Express（:3001）+ PostgreSQL（库 codereview） |
| 模型 | OpenAI 兼容 /v1/chat/completions（默认 opencode.ai 通道，可内网自建） |
| 构建 | electron-builder 25.1.8，`--win dir` → win-unpacked → zip（153M，含 ocr native）；绝不用 npx |
| 远端 | GitHub `SCrazying/CodeReviewSystem`，仅 master + 语义化 tag push |

## 3. 客户端模块设计

### 3.1 主进程 IPC 一览
`config:get/save`、`llm:models`、`llm:validate`（保存即校验）、`review:run`、`review:stop`、`review:post`、`commit:post`、`fix:run`、`fix:commit`、`fix:status`、`mrs:list`、`mrs:history`、`commits:list`、`reviews:list`、`schedule:list/create/update/delete`、`gate:status/heartbeat/recheck`、`server:test`、`clip:write`、`open:url/commit`、`ui:zoom`。

### 3.2 审查执行 review-backend.js
- `runReview(iid)` / `runCommitReview(sha)` → 先 `syncOcrConfig`（客户端 LLM → 便携 provider=app）→ `findOcrExe` 定位 native → `runNative`。
- `runChild(bin, args, cwd, model, env, timeoutMs)`：`execFile` + `exit` 事件区分三种退出（正常/手动停止/超时），异常退出 8 秒内等 stderr 拿真实原因；Windows 停止 `execFileSync('taskkill', ['/F','/T','/PID',..])`。
- ocr 变更参数：`--from origin/main --to <head sha> --format json --model <模型> --concurrency <N> --timeout <设置-5> [--background 中文指令]`。
- env：`OCR_LLM_URL/OCR_LLM_TOKEN/OCR_LLM_MODEL`（仅有效值注入）、`OCR_MODEL`、`OCR_NO_UPDATE=1`、`USERPROFILE=便携目录(string)→`.opencodereview`。
- 便携目录：dev=`client/`；打包=`win-unpacked/resources/app.asar.unpacked/`（从 exe 真实路径推导，**不能**用 `__dirname`——asar 虚拟路径会 mkdir 失败）。

### 3.3 回填
- `postComments(iid, log, existingReview, selectedComments)`：清理脏 PENDING review → 复用 review（子集）→ 去重 → Gitea `POST /pulls/{iid}/reviews`（commit_id=mr.sha，行级 comments）→ GitLab `POST /merge_requests/{iid}/discussions`（真实 base/start/head sha）。
- `postCommitComments(sha, review, log)`：GitLab 提交评论（`/repository/commits/:sha/comments`）或按关联 MR 分流。
- 评论体 `fmtCommentBody(c)`：`描述 + 📄问题代码 + 🔧修复建议`，按扩展语法高亮（30+ 语言映射）。
- 仓库一致性：`currentRepoKey = url|project|repoDir`，三处复用判断 + 历史回填自动切换均基于它。

### 3.4 自动修复 fix-engine.js
- 入参：`review`（含 `srcBranch`/comments）+ `base`（`review.srcBranch`（MR 源分支）或 `commit:<sha>` 或 `main`）。
- 流程：确保源分支（fetch origin 相应 ref → checkout）→ `git checkout -B fix/ai/<base>-mr-N` → 逐问题：`applyFix`（≤阈值整文件重写 / 大文件 unified diff + `git apply --3way` 校验）→ `git add -A` → `git commit -m 【fix】… -m 【问题单号】…` → 收集 sha →（开启时）`git push -u origin`。
- `lastFix` 记录 + `reportFix` 上报队列。

### 3.5 定时任务（客户端）
- 数据：`config.schedules[]`（id/name/repoIndex/intervalMin/startTime/enabled）。
- 调度：`restartScheduler()`（配置保存/启动时调用）→ `setInterval(schedTick, 60s)`。
- 触发：`now ≥ nextScanTime`（startTime：当天该时刻首算/已过→明天；无 startTime：立即 → 之后按 interval 递增）。
- 执行：临时 `new ReviewBackend(repo)`（不打断当前 backend）→ `listMRs` → 对比 `lastIds` → 新 MR 发 `mrs:refresh(repoIndex)`。

### 3.6 历史
- `reviews-history.json`（userData），`saveReviewHistory`（上限 500 滚动），`loadHistory`。
- 审查完成写入：MR（`{repoKey, repoProject, object:'MR !N', iid, comments…}`）/ 提交（sha）。

## 4. 服务端设计

### 4.1 表结构（db/schema.sql，11 张）
| 表 | 用途 |
|---|---|
| admin_users | 管理后台账号 |
| client_tokens | 客户端令牌（心跳鉴权 X-Client-Token） |
| repos | 仓库（url/project/name/token…） |
| reviews | 审查记录（MR/提交、模型、条数） |
| review_issues | 审查问题明细（path/line/severity/category/content…） |
| fix_runs | 自动修复运行（分支、结果） |
| fix_commits | 修复 commit（sha/subject） |
| usage_logs | 使用/推送记录 |
| scheduled_tasks / task_runs | 服务端定时兼容表（本期客户端化，保留） |
| llm_config | LLM 配置快照 |

### 4.2 接口
`/api/health`、`/api/auth/*`（登录/心跳）、`/api/repos*`、`/api/reviews*`、`/api/fixes*`、`/api/tasks*`、`/api/stats`；管理后台 `web/index.html`。

## 5. 关键机制
- **每日卡控**：客户端启动/进入时 `gate:heartbeat`；失败可 `超级管理员授权`（本地 sha256 校验，永久免验证）。授权前禁用审查/回填/修复。
- **记录队列**：审查/修复/用量 jsonl 持久化；每 30s 尝试推送；连续失败达 3 次自动暂停；「📤 推送」手动强制重试并重置计数。
- **LLM 保存即校验**：`llm:validate` 先 `/v1/models` 再真实极小 `chat/completions`（部分网关 /models 不鉴权，用真实请求测出 401/404）。

## 6. 打包与发布
```
export ELECTRON_BUILDER_BINARIES_MIRROR="https://gh-proxy.com/..."
taskkill /F /IM electron.exe & /IM CodeReviewTool.exe   # 清锁文件
node_modules/.bin/electron-builder --win dir -c.win.signAndEditExecutable=false
powershell Compress-Archive win-unpacked\* → dist/CodeReviewTool-win-x64.zip (153M)
git tag -a vX.Y.Z -m … && git push origin master && git push origin vX.Y.Z
```
注意：打 zip 前必须清理仍在运行的实例（文件锁）；用户明确要求打包时才打包/推 tag。
