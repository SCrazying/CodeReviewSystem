## 1. 数据库设计 (PostgreSQL)

### 1.1 ER 概览

```
admin_users ─┬─< client_tokens
             └─< (审计日志)
repos ─┬─< reviews ──┬─< review_issues
       │             └─< review_usage
       ├─< fix_runs ──┬─< fix_commits
       └─< scheduled_tasks ──< task_runs
llm_configs(单行配置)
```

### 1.2 建表 SQL

```sql
-- 管理员
CREATE TABLE admin_users (
  id            SERIAL PRIMARY KEY,
  username      TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,          -- bcrypt
  created_at    TIMESTAMPTZ DEFAULT now()
);

-- 客户端授权 token
CREATE TABLE client_tokens (
  id         SERIAL PRIMARY KEY,
  token      TEXT UNIQUE NOT NULL,
  machine    TEXT,                      -- 备注: 机器名/使用者
  enabled    BOOLEAN DEFAULT true,
  created_at TIMESTAMPTZ DEFAULT now(),
  last_seen  TIMESTAMPTZ
);

-- 仓库注册表(服务端视角: 定时任务用)
CREATE TABLE repos (
  id          SERIAL PRIMARY KEY,
  name        TEXT NOT NULL,
  git_url     TEXT NOT NULL,            -- Gitea/GitLab 地址
  project     TEXT NOT NULL,            -- 项目路径 admin/xxx
  token       TEXT,                     -- Git 服务 token(服务端存)
  git_type    TEXT DEFAULT 'gitea',     -- gitea | gitlab
  local_path  TEXT,                     -- 可选: 服务端本地克隆路径
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 审查记录(客户端 + 定时任务统一入口)
CREATE TABLE reviews (
  id            SERIAL PRIMARY KEY,
  repo_id       INTEGER REFERENCES repos(id),
  repo_name     TEXT NOT NULL,
  source        TEXT NOT NULL,          -- client | scheduler
  target_type   TEXT NOT NULL,          -- mr | commit
  target_id     TEXT NOT NULL,          -- MR iid 或 commit sha
  target_title  TEXT,
  src_branch    TEXT,
  dst_branch    TEXT,
  status        TEXT DEFAULT 'done',    -- done | failed | partial
  model         TEXT,
  duration_ms   INTEGER,
  input_tokens  BIGINT DEFAULT 0,
  output_tokens BIGINT DEFAULT 0,
  request_count INTEGER DEFAULT 0,      -- 大模型请求次数
  error_msg     TEXT,
  created_at    TIMESTAMPTZ DEFAULT now()
);

-- 问题明细(一条审查多条问题)
CREATE TABLE review_issues (
  id          SERIAL PRIMARY KEY,
  review_id   INTEGER NOT NULL REFERENCES reviews(id) ON DELETE CASCADE,
  path        TEXT NOT NULL,
  start_line  INTEGER,
  end_line    INTEGER,
  severity    TEXT NOT NULL,            -- high | medium | low | security
  category    TEXT,
  content     TEXT NOT NULL,
  suggestion  TEXT,
  fix_status  TEXT DEFAULT 'none',      -- none | fixed | skipped
  fix_run_id  INTEGER,                  -- 关联修复运行
  created_at  TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_issues_review ON review_issues(review_id);
CREATE INDEX idx_issues_severity ON review_issues(severity);
CREATE INDEX idx_issues_path ON review_issues(path);

-- 自动修复运行
CREATE TABLE fix_runs (
  id          SERIAL PRIMARY KEY,
  review_id   INTEGER NOT NULL REFERENCES reviews(id),
  repo_name   TEXT NOT NULL,
  base_branch TEXT NOT NULL,            -- MR 原始源分支
  fix_branch  TEXT NOT NULL,            -- fix/ai/<mr-id>-<ts>
  issue_count INTEGER DEFAULT 0,
  commit_count INTEGER DEFAULT 0,
  status      TEXT DEFAULT 'created',   -- created | adopted | discarded
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 修复 commit 明细
CREATE TABLE fix_commits (
  id          SERIAL PRIMARY KEY,
  fix_run_id  INTEGER NOT NULL REFERENCES fix_runs(id) ON DELETE CASCADE,
  sha         TEXT,
  message     TEXT,
  issue_id    INTEGER REFERENCES review_issues(id),
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 用量明细(每次 LLM 调用)
CREATE TABLE usage_logs (
  id             SERIAL PRIMARY KEY,
  review_id      INTEGER REFERENCES reviews(id),
  source         TEXT DEFAULT 'client', -- client | scheduler | fix
  model          TEXT NOT NULL,
  input_tokens   BIGINT NOT NULL DEFAULT 0,
  output_tokens  BIGINT NOT NULL DEFAULT 0,
  request_count  INTEGER NOT NULL DEFAULT 1,
  cost_estimate  NUMERIC(10,4) DEFAULT 0,  -- 按配置单价估算
  created_at     TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_usage_time ON usage_logs(created_at);
CREATE INDEX idx_usage_model ON usage_logs(model);

-- 定时任务
CREATE TABLE scheduled_tasks (
  id            SERIAL PRIMARY KEY,
  name          TEXT NOT NULL,
  repo_id       INTEGER NOT NULL REFERENCES repos(id),
  mode          TEXT NOT NULL,          -- open_mrs | branch | commit
  branch        TEXT,                   -- mode=branch 时目标分支
  cron          TEXT NOT NULL,          -- cron 表达式
  enabled       BOOLEAN DEFAULT true,
  post_to_git   BOOLEAN DEFAULT false,  -- 是否回填评论
  model         TEXT,
  created_at    TIMESTAMPTZ DEFAULT now()
);

-- 定时任务执行历史
CREATE TABLE task_runs (
  id           SERIAL PRIMARY KEY,
  task_id      INTEGER NOT NULL REFERENCES scheduled_tasks(id) ON DELETE CASCADE,
  started_at   TIMESTAMPTZ DEFAULT now(),
  finished_at  TIMESTAMPTZ,
  status       TEXT DEFAULT 'running',  -- running | success | failed
  reviews_created INTEGER DEFAULT 0,
  error_msg    TEXT
);

-- LLM 配置(单行)
CREATE TABLE llm_config (
  id         INTEGER PRIMARY KEY CHECK (id = 1),
  provider   TEXT NOT NULL DEFAULT 'opencode',
  base_url   TEXT,
  api_key    TEXT,
  model      TEXT NOT NULL DEFAULT 'deepseek-v4-flash',
  price_in   NUMERIC(10,6) DEFAULT 0,   -- 每 1K token 价格(估算用)
  price_out  NUMERIC(10,6) DEFAULT 0
);
```

### 1.3 数据保留与归档

- 默认保留全部;管理端可导出 `reviews + issues` CSV/JSON(按时间范围)
- 归档导出文件存服务端 `archive/` 目录,带日期命名

## 3. 定时任务调度设计

### 3.1 调度器

- 基于 `node-cron`:启动时加载 `scheduled_tasks` 中 enabled 的任务,注册 cron
- 任务触发 → `executor.run(task)`:
  1. 创建 `task_runs` 记录(running)
  2. 确保本地克隆(服务端 `repos.local_path` 或临时目录 `work/<repo>`)
  3. 按 mode 枚举审查目标:
     - `open_mrs`:API 获取 open MR 列表
     - `branch`:检查该分支相对默认分支的 diff
     - `commit`:最新 N 个提交
  4. 逐目标执行审查流水线(复用 ocr),结果入库(reviews + issues + usage)
  5. `post_to_git` 时回填评论
  6. 更新 task_runs(status/finished_at/reviews_created)
- 失败处理:重试 3 次(指数退避),最终失败记录 error_msg
- 并发控制:同一任务不并发执行(锁:running 状态检查);全局并发限 2

### 3.2 审查流水线(共享)

```
reviewPipeline({repo, targetType, targetId, branches, postToGit, model})
  → 校验授权 → fetch → ocr review(JSON) → 解析问题
  → 写 reviews + issues + usage(事务)
  → postToGit ? 回填评论(去重) : 跳过
  → 返回 {reviewId, issues, usage}
```

## 4. 客户端模块设计

### 4.1 git-service.js(核心接口)

```js
listBranches(repoDir)            // 本地分支列表
listAllBranches(repoDir)         // 含远端
getCommitTree(repoDir, {all})    // 提交树: {nodes:[{sha,msg,author,date,branches,isHead,mr}], edges}
getCommitDetail(repoDir, sha)    // 单提交: 文件列表 + diff 统计
getMrCommits(api, iid)           // MR 关联提交(远端 API)
diffForCommit(repoDir, sha)      // 相对父提交的 diff(供 ocr)
diffForMr(api, iid)              // MR 分支对比
createFixBranch(repoDir, base, name)
applyPatchAndCommit(repoDir, patch, msg)   // 自动修复
```

### 4.2 提交树数据结构

```json
{
  "branch": "feature/x",
  "all": false,
  "nodes": [
    {
      "sha": "9bd63e68",
      "msg": "fix: 写盘失败删除截断文件",
      "author": "autotest-dev",
      "date": "2026-08-16T22:36:41+08:00",
      "branches": ["feature/fix-ocr-issues"],
      "isHead": true,
      "mr": { "iid": 1, "title": "fix: ...", "state": "open" }
    }
  ]
}
```

### 4.3 修复引擎(逐问题 commit)

```
1. 获取问题清单(按 severity: security > high > medium > low)
2. 对每个问题:
   a. 读取文件上下文(±15 行)
   b. LLM 生成补丁(unified diff)
   c. 校验补丁:git apply --check
   d. git apply → git add → git commit -m "fix(ai): #<n> <title> [MR!<iid>]"
   e. 失败 → 跳过, 记录 skipped
3. 汇总 → 上报 fix_runs + fix_commits
```

### 4.4 离线缓冲

- 本地 `userData/queue.jsonl`:未上报的 reviews/fixes/usage
- 心跳成功时 flush(逐条 POST,失败保留)
- 队列上限 5000 条,超出丢弃最旧并标记

## 6. 关键流程时序

### 6.1 客户端 MR 全自动审查

```
用户点击"审查 MR !3"
  → auth-gate 心跳校验(失败则提示离线)
  → git-service fetch origin + fetch refs/pull/3/head
  → review-backend.runReview(3)      # ocr review --from base --to head
  → 用量采集(manifest tokens)
  → renderer 展示意见卡片
  → [自动回填开启] postComments(去重) → Git 服务
  → report-queue 上报 {reviews, issues, usage}
  → [自动修复开启] fix-engine: 建分支 → 逐问题补丁 commit → 上报 fix_runs
```

### 6.2 定时任务执行

```
node-cron 触发 → executor.run(task)
  → task_runs(running)
  → 克隆/更新 work/<repo>
  → 枚举 MR 列表 → 逐个 reviewPipeline
  → 回填(可选) → 写库 → task_runs(success)
  → 异常: 重试3次 → task_runs(failed, error_msg)
```

## 附录 B: 客户端设置模块设计(REQ-S01~S08)

### config.json 数据模型(客户端)

```json
{
  "url": "http://localhost:3000",        // Git 服务地址
  "token": "",                            // Git API Token
  "project": "admin/autotest",            // 远端项目
  "repoDir": "D:/repo",                   // 本地仓库目录
  "model": "deepseek-v4-flash",           // 审查模型
  "serverUrl": "http://127.0.0.1:3001",   // 服务端地址
  "clientToken": "",                      // 服务端客户端 Token
  "autoPost": false,                      // 审查后自动回填评论
  "autoFix": false,                       // 审查后自动修复分支
  "reviewDepth": "standard",              // fast | standard | deep
  "llmBaseUrl": "https://opencode.ai/zen/go/v1",
  "llmApiKey": "",                        // 修复引擎(留空用环境变量)
  "fixModel": "deepseek-v4-flash",
  "theme": "dark",                        // dark | light | system
  "fontSize": "medium",                   // small | medium | large
  "repos": [                              // 多仓库列表
    { "name": "AutoTest", "url": "http://localhost:3000", "token": "...",
      "project": "admin/autotest", "repoDir": "D:/AI/Code/AutoTest" },
    { "name": "dsh-desktop", "url": "http://localhost:3000", "token": "...",
      "project": "admin/dsh-desktop", "repoDir": "D:/AI/github/dsh-desktop" }
  ],
  "activeRepo": 0                         // 当前激活仓库下标
}
```

### 多仓库机制

- 配置层: `repos[]` + `activeRepo` 下标; 顶层 url/token/project/repoDir 由激活仓库同步展开(兼容旧单仓库路径)
- 主进程: `activeRepoConfig()` 展开激活仓库 → 构造 ReviewBackend; 保存配置时自动同步激活仓库到顶层字段
- 前端: 设置页"Git 仓库"分组维护列表(新增/编辑/删除/设为当前); 主页顶部下拉切换 = 保存 activeRepo + 重建 backend + 刷新 MR/提交树
- 切换即时生效(卡控通过时), 日志提示当前仓库

### 生效机制

- `config:save` 落盘后:主进程重建 ReviewBackend/FixEngine(注入 llm/auto* 配置),渲染进程按 theme/fontSize 立即应用
- 自动回填: `review:run` 成功后,若 `config.autoPost && target.type==='mr'` → 自动调 postComments
- 自动修复: 同上, `config.autoFix` → 自动调 runFix(基于 MR 原始分支)
- 主题: 渲染进程 `document.documentElement.dataset.theme`,CSS 双主题变量;fontSize 映射根字号

### 界面结构(Codex 风格)

```
主界面(左侧导航)
├── 审查(默认)  → 顶部: 仓库▾ | 分支▾ | 全部☑ | 服务端状态   [MR 列表 | 提交树]
├── 设置        → 分组卡片: 连接 / Git / 审查 / LLM / 外观 / 关于
└── 日志        → 运行日志(原右栏)
设置页所有开关即时生效, 主界面顶部保留精简配置条(快速改仓库/分支)
